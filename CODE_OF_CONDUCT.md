# Code of conduct

## The short version

Be decent to people. Argue with the code, not the person who wrote it.

## What's expected

- Assume the other person is competent and acting in good faith. Most disagreements here are about a rule's threshold, not about anyone's intelligence.
- Critique proposals plainly and specifically. "This will fire on every skill in my repo, here's an example" is exactly the feedback this project needs. "This is stupid" is not.
- Accept that a rule can be rejected on the merits. skillcheck's usefulness depends on keeping the false-positive rate near zero, so "good idea, too noisy" is a normal and final answer.
- Credit people's work. If someone's report led to a fix, say so in the PR.

## What isn't

Harassment, personal attacks, discriminatory language, sustained disruption, or publishing someone's private information. Also: don't use issues or PRs to advertise.

## Scope

This applies in the repository — issues, pull requests, discussions, commit messages — and anywhere someone is representing the project.

## Enforcement

Report a problem privately to the maintainers via a [security advisory](https://github.com/mirawren/skillcheck/security/advisories/new) (it's the private channel this repo has) or by email to the address on the maintainer's GitHub profile. Reports stay confidential.

Maintainers may edit or remove content, and may block accounts, when this document is violated. Consequences scale with severity and repetition: usually a warning first, a block for anything sustained or deliberate.

Maintainers are held to the same standard as everyone else, and more visibly.
